# 퇴근 승인 바랍니다 — Game Design Document

**엔진:** Godot 4.x (GDScript)  
**장르:** 방탈출 싱글플레이어 (텍스트+이미지 퍼즐 혼합)  
**예상 플레이 시간:** 40~50분  
**엔딩:** 6종

---

## 1. 핵심 컨셉

> 회사 = 방탈출 맵 / 업무 = 퍼즐 / 퇴근 = 탈출

플레이어는 오늘 중으로 퇴근 승인을 받아야 한다. 퍼즐을 어떻게 푸느냐(정석/꼼수/반항)가 엔딩을 결정한다.

---

## 2. 상태 변수 (GameState 싱글턴에 저장)

| 변수 | 초기값 | 변화 방식 | 엔딩 영향 |
|------|------|---------|---------|
| `accuracy` | 0 | 퍼즐 정석 풀이 +1, 오답 -1 | 높음 → 정상/완벽 퇴근 |
| `stress` | 0 | 퍼즐 실패/야근 이벤트 +1 | 7 이상 → 야근 엔딩 위험 |
| `resistance` | 0 | 반항 선택지 +1 | 7 이상 → 칼퇴/퇴사 엔딩 |
| `conformity` | 0 | 순응 선택지 +1 | 10 이상 → 회사의 일부 엔딩 |
| `overtime_flag` | 0 | 시간 초과/야근 선택 +1 | 3 이상 → 야근 엔딩 |
| `hidden_clues` | [] | 히든 메시지 수집 시 추가 | 4개 이상 → 히든 루트 해금 |
| `time_remaining` | 540분 (09:00) | 이벤트 단위 감소 (10. 시간 시스템 표 참조) | 18:00 도달 → 야근 엔딩 |

## 4. 퍼즐 10개 상세 명세

### 퍼즐 1: 출근 기록 확인
- **위치:** 사무실 → 컴퓨터
- **유형:** 숫자 입력 (4자리)
- **상황:** 출근 시스템에 `08:??` 오류
- **단서 위치:**
  | 단서 | 위치 | 시간 |
  |------|------|------|
  | 커피 영수증 | 책상 위 | 08:42 |
  | 엘리베이터 로그 | 서랍 속 문서 | 08:47 |
  | 보안게이트 기록 | 컴퓨터 파일 | 08:49 |
  | 메신저 첫 메시지 | 메신저 앱 | 08:53 |
- **정답:** `0849` (보안게이트 기준 = 회사 공식 출근 기준)
- **풀이 분기:**
  - `0849` → accuracy +1
  - `0842` → accuracy -1, resistance +1
  - 버튼 5회 클릭(반항) → 히든 메시지 1 획득
- **Godot 구현:** **자체 숫자 키패드 UI** (NumPadInput 재사용 컴포넌트) — 입력란은 read-only Label, 0~9/⌫/↵ 버튼으로 4자리 입력 → 정답 비교 → GameState 업데이트

---

### 퍼즐 2: 메일 정리
- **위치:** 사무실 → 컴퓨터 → 메일함
- **유형:** 분류 선택 (중요/일반/스팸)
- **상황:** 메일 20개 수신. 5개 핵심 메일 분류
- **핵심 메일:**
  | 메일 | 올바른 분류 |
  |------|---------|
  | 거래처 확인 요청 | 중요 |
  | 퇴근 승인 공지 | 중요 |
  | 보안 업데이트 | 중요 |
  | 부장님 전달 사항 | 중요 |
  | IT팀 공지 | 중요 |
- **함정 메일:** "급함!!!" → 스팸 / "긴급회의 17:30" → 일반(참석자 없음)
- **클리어 조건:** 5개 중 4개 이상 정확 분류
- **보상:** 일정표 아이템 획득, 퍼즐 3 해금
- **반항 처리:** 전체 읽음 처리 → 히든 메일 해금
- **Godot 구현:** 메일 리스트 UI (`VBoxContainer`) + 각 메일 클릭 시 분류 팝업

---

### 퍼즐 3: 회의 일정 맞추기
- **위치:** 회의실
- **유형:** 이미지 퍼즐 (도형/시간 선택)
- **상황:** 팀원 4명 일정 겹침 찾기
- **함정:** 17:30 = 자동 야근 처리 규정
- **정답:** 17:00
- **반항:** 회의 거부 → "메일 대체" → resistance +1, hidden_clues 추가
- **Godot 구현:** 일정표 이미지 + 클릭 가능한 시간 슬롯

---

### 퍼즐 4: 상사 지시 해석
- **위치:** 사무실 (여러 단서 탐색)
- **유형:** 조사 + 선택지
- **상황:** "그거 적당히 알아서 빨리 처리해"
- **단서:**
  | 단서 | 위치 |
  |------|------|
  | "A안은 절대 제출 금지" | 책상 포스트잇 |
  | 보고서_B_수정.docx | 컴퓨터 공유폴더 |
  | 3분기 수치 | 회의실 화이트보드 |
  | 이전 메일 히스토리 | 메일함 |
- **정답:** 보고서_B_수정 → PDF 변환 → 3분기 수치 반영 → 제출
- **반항:** 인사팀 문의 → 히든 메시지 2 획득
- **Godot 구현:** 탐색 클릭 → 메모 팝업 → 최종 선택지 4개 제시

---

### 퍼즐 5: 엑셀 매출 계산
- **위치:** 사무실 → 컴퓨터
- **유형:** 이미지 퍼즐 (그래프/표 읽기)
- **조건:** 05/01~05/02 + 상태=완료 + 부서=영업1팀 합계
- **정답:** 120 + 250 = 370 → 코드 `0370`
- **함정:** 숨겨진 시트 `ANSWER_DO_NOT_OPEN`에 답 노출 (꼼수 루트)
- **Godot 구현:** 스프레드시트 이미지 + **자체 숫자 키패드 UI** (NumPadInput 재사용)

---

### 퍼즐 6: 복사기 고장
- **위치:** 복사실
- **유형:** 이미지 퍼즐 (순서 클릭)
- **오류:** `ERROR 404: PAPER NOT FOUND` (용지는 있음)
- **정답 순서:** 토너함 열기 → 관리자 버튼 → 급지함 닫기 → 초록 버튼 → 빨간 버튼
- **실패 패널티:** 기본 오답 -5분에 더해 전원 버튼 추가 -3분, 급지함 먼저 추가 -2분 (10.3 표 참조)
- **히든:** 3회 실패 시 로그 출력 → B1 비상구 단서
- **Godot 구현:** 복사기 이미지 + 클릭 가능한 버튼들 (`Area2D`) + 순서 배열 비교

---

### 퍼즐 7: 결재 라인 맞추기
- **위치:** 사무실 → 결재 시스템
- **유형:** 이미지 퍼즐 (도형 연결)
- **조건:** 금액 80만원 + 퇴근 승인 관련
- **규정 단서:**
  - 100만원 미만 → 팀장 전결
  - 퇴근 관련 → 인사팀 확인 필수
- **결재자 목록 (이미지화, 노드별 캐릭터 아바타):**
  | 노드 | 아바타 |
  |------|--------|
  | 본인 (사원님) | 사원증 실루엣 |
  | 팀장 | 팀장 캐릭터 일러스트 |
  | 인사팀 | 인사팀 캐릭터 일러스트 |
  | 대표이사 | **핑크 토끼 사장 일러스트** ({CEO_NAME}) — 오답 함정 (100만원 미만이라 불필요) |
  | 본인(반항용) | 사원증 실루엣 |
- **정답:** 팀장 → 인사팀
- **함정:** 대표이사 경유 → 권한 초과 오류 (오답 처리, -5분)
- **반항:** 결재자에 본인 이름 → 권한순환 오류 메시지
- **Godot 구현:** 결재 흐름도 이미지 + **드래그로 노드 연결** — 출발 노드 hitbox는 base 기준 최소 120×120px(손가락 호환), 드래그 중에는 가이드 라인 시각 표시, 도착 노드 위에서 자동 스냅. 결재자 노드는 `pc_screen_approval` 내 자식 자산으로 `npc_avatar_*` 명명

---

### 퍼즐 8: 탕비실 암호
- **위치:** 탕비실
- **유형:** 관찰 + 숫자 입력
- **단서:** 재고표 감소량 (종이컵 6 / 믹스커피 3 / 아메리카노 2 / 녹차 1)
- **정답:** 감소량 순서 → `4213` (4번째/2번째/1번째/3번째 순위)
- **히든:** 냉장고 뒤 메모 → 비상계단 카드키 획득
- **Godot 구현:** 탕비실 배경 이미지 + 재고표 클릭 팝업 + 냉장고 클릭 히든 + **자체 숫자 키패드 UI** (NumPadInput 재사용)

---

### 퍼즐 9: 퇴근 승인 시스템
- **위치:** 사무실 → 컴퓨터 → 퇴근 시스템
- **유형:** UI 퍼즐 (체크박스 조작)
- **함정:** 체크 시마다 새 업무 생성 (무한루프)
- **해결:** 체크박스 이름 첫 글자 조합 = "오늘은퇴근하라" → 해당 항목만 체크
- **정답 체크:** "퇴근 승인", "근무 종료 보고"
- **반항:** 시스템 로그 다이얼로그에서 **`[ loop=false 로 변경 ]` 명령 버튼** 선택 → 퇴사 엔딩 해금 (자유 텍스트 편집 아님)
- **Godot 구현:** `CheckBox` 배열 + 동적 업무 생성 로직 + 로그 뷰어 (사전 정의 명령 버튼 1~3개 노출)

---

### 퍼즐 10: 야근 유도 대화 회피
- **위치:** 사무실 출구 앞
- **유형:** 선택지 대화
- **상황:** 퇴근 직전 "잠깐 시간 괜찮아?"
- **선택지:**
  | 선택 | 결과 |
  |------|------|
  | "네, 괜찮습니다." | overtime_flag +1 → 야근 |
  | "내일 오전에 바로 확인하겠습니다." | 최선 → 정상 퇴근 |
  | "죄송합니다. 지금은 어렵습니다." | resistance +1 → 반항 증가 |
- **Godot 구현:** 대화 팝업 + 선택지 버튼 3개

## 5. 히든 루트: 비상계단

**해금 조건:** `hidden_clues` 배열에 4개 이상 수집 + `card_key` 인벤토리 보유

히든 메시지 수집처:
| 번호 | 메시지 | 획득 방법 |
|------|------|---------|
| 1 | "퇴근은 승인받는 것이 아니다." | 퍼즐1 버튼 5회 클릭 |
| 2 | "불명확한 지시는 권력이 아니라 오류다." | 퍼즐4 인사팀 문의 |
| 3 | "반복은 시스템의 실패다." | 퍼즐6 3회 실패 로그 |
| 4 | "책상은 감옥의 가장 작은 형태다." | 포스트잇 뒷면 |
| 5 | "퇴근하고 싶다면 냉장고 뒤를 봐." | 탕비실 냉장고 |

비상계단 최종 선택:
- 회사 밖으로 나간다 → 칼퇴 엔딩
- 자리로 복귀한다 → 회사의 일부 엔딩
- 시스템 종료 버튼 누른다 → 퇴사 엔딩

## 9. 빌드 타겟 호환 (Web / Desktop / Android)

이 게임은 **Web(HTML5) + Desktop(Win/Mac/Linux) + Android** 3개 타겟에서 동작한다. iOS 미지원.

### 9.1 입력 정책 (전 퍼즐 공통)

- **호버 의존 금지** — Android에 호버 없음. 시각 피드백은 idle/active 두 상태로 미리 그리고 탭으로 토글
- **사운드 의존 단서 금지** — Web 첫 진입 시 자동재생 차단
- **자유 텍스트 입력 금지** — 모든 텍스트성 입력은 ① 자체 숫자 키패드 ② 사전 정의 명령 버튼 ③ 토글/스위치 중 하나로 대체
- **터치 영역 최소 88×88px** (드래그 시작 노드는 120×120px 권장)

### 9.2 NumPadInput 공통 컴포넌트

퍼즐 1, 5, 8 등 숫자 입력은 단일 재사용 씬으로 구현:

```
NumPadInput (Control)
├─ Display       (Label, read-only, 입력란)
├─ Keypad        (GridContainer 3×4)
│   ├─ Btn0..Btn9 (TextureButton, 88×88 이상)
```

## 10. 시간 시스템 (이벤트 기반)

### 10.1 정책

- **실시간 카운트다운 아님** — 시계는 플레이어의 행동 단위로만 진행
- **표시 형식**: 게임 내 회사 시계 `09:00 → 18:00`. 헤더 우측 상단 항상 표시. 분침 줄어들 때 0.3초 강조 (펄스)
- **종료 처리**: `18:00` 도달 시 즉시 끊지 않고, **현재 진행 중인 퍼즐/대화 마무리 후** 야근 엔딩 트리거
- **일시정지 개념 불필요** (실시간 X) — 메뉴/인벤토리/Android 백그라운드 모두 시간 영향 없음
- 내부 표현: `time_remaining: int` (분 단위, 540 → 0)

### 10.2 이벤트별 감소량 표

| 이벤트 | 감소 | 비고 |
|--------|------|------|
| 퍼즐 정답 클리어 | -3분 | 진행 보상이 아니라 "퍼즐을 푸는 데 든 시간" 표현 |
| 퍼즐 오답/실패 | -5분 | 실수 페널티. 퍼즐별 추가 페널티 가능 (예: 퍼즐 6) |
| 씬 이동 | -2분 | 사무실 ↔ 회의실/복사실/탕비실/비상계단 |
| 선택지 결정 (대화) | -1분 | 퍼즐 4, 10 등 |
| 단서 탐색 탭 | 0~1분 | 같은 오브젝트 첫 탭만 -1분, 재탭은 0분 (반복 페널티 방지) |
| 인벤토리 사용 | ±0분 | 행동에 포함되어 있다고 간주 |

### 10.3 퍼즐별 추가 페널티 (룰 위에 덧붙음)

| 퍼즐 | 추가 페널티 |
|------|-----------|
| 퍼즐 6 (복사기) | 전원 버튼 추가 -3분, 급지함 먼저 추가 -2분 (오답에 포함하지 않고 별도 가산) |

### 10.4 GameState 인터페이스

```gdscript
# GameState autoload
signal time_changed(new_minutes_left: int, delta: int)
signal time_expired

func consume_time(event: StringName) -> void:
    var delta := TIME_COST.get(event, 0)
    time_remaining = max(0, time_remaining - delta)
    time_changed.emit(time_remaining, -delta)
    if time_remaining == 0:
        time_expired.emit()   # 트리거 후 EndingManager가 현재 흐름 마무리 대기

const TIME_COST := {
    &"puzzle_solved":   3,
    &"puzzle_failed":   5,
    &"scene_change":    2,
    &"choice_made":     1,
    &"clue_first_tap":  1,
    &"clue_repeat_tap": 0,
    &"inventory_use":   0,
}
```

각 퍼즐/씬/선택지 코드에서는 `GameState.consume_time(&"puzzle_solved")` 식으로 호출. 추가 페널티는 별도 `consume_time` 호출로 누적.

## 11. 저장 / 체크포인트

### 11.1 정책

- **자동 저장 only** — 수동 저장 버튼 없음
- **트리거**: 퍼즐 클리어 직후 (정답 처리 완료 시점)
- **슬롯**: 단일 슬롯, 덮어쓰기 (멀티 슬롯 불필요)
- **재진입**: 메인 메뉴에서 `[이어하기]` 선택 시 마지막 클리어 시점의 **씬 기본 진입 위치**로 복귀 (퍼즐 화면 도중에 떨어뜨리지 않음)
- **새 게임**: 기존 세이브를 덮어쓰기 전 1회 확인 다이얼로그
- **실패 fallback**: Web 시크릿 모드/IndexedDB 차단 등으로 저장 실패 시 → 메인메뉴에 `"이 환경은 저장이 차단되어 있습니다 (세션 동안만 진행 유지)"` 배너 + 메모리 저장으로만 진행

### 11.2 저장 데이터 (JSON)

```json
{
  "version": "1.0",
  "saved_at": "2026-05-12T14:32:00",
  "scene": "office",
  "state": {
    "accuracy": 6,
    "stress": 2,
    "resistance": 3,
    "conformity": 1,
    "overtime_flag": 0,
    "hidden_clues": ["clue_2", "clue_4"],
    "time_remaining": 478
  },
  "inventory": ["schedule_paper", "card_key"],
  "puzzles_cleared": ["puzzle_01", "puzzle_02", "puzzle_06"],
  "endings_unlocked": ["ending_normal", "ending_overtime"]
}
```

- 자산 데이터 저장 금지 (Web localStorage ~10MB 한도, 자산은 매번 로드)
- 위 데이터 크기 ≤ 4KB 예상 (한도 여유 충분)
- **`endings_unlocked`는 다회차 누적** — 새 게임 시작 시 다른 데이터는 초기화되지만 `endings_unlocked`는 보존된다 (인사 평가 기록의 의미)

### 11.3 GameState 인터페이스

```gdscript
const SAVE_PATH := "user://save.json"

signal save_succeeded
signal save_failed(reason: String)

func autosave() -> void:
    var data := _serialize()
    var f := FileAccess.open(SAVE_PATH, FileAccess.WRITE)
    if f == null:
        save_failed.emit("filesystem_blocked")
        return
    f.store_string(JSON.stringify(data))
    save_succeeded.emit()

func has_save() -> bool:
    return FileAccess.file_exists(SAVE_PATH)

func load_save() -> bool:
    if not has_save(): return false
    var f := FileAccess.open(SAVE_PATH, FileAccess.READ)
    var data: Dictionary = JSON.parse_string(f.get_as_text())
    _deserialize(data)
    return true
```

각 퍼즐 클리어 처리 마지막에 `GameState.autosave()` 호출. `save_failed` 시그널을 메인 UI가 구독해 배너 표시.

## 12. UI 텍스트 톤 가이드

### 12.1 톤 정의

- **블랙코미디 풀파워** — 회사 = 방탈출, 업무 = 퍼즐, 시스템 = 감시자라는 전제를 텍스트로 강화
- 시스템 메시지 = **공문체 + 의도적 코퍼릿 사족** (예: "확인 부탁드립니다", "검토 후 회신드리겠습니다")
- 단답·결론만 던지지 않고 **사족으로 답답함을 연출**해 풍자 강화
- 플레이어 호칭은 **이름 없이 "사원님"**

### 12.2 코퍼릿 어휘 사전 (적극 사용)

| 표현 | 사용처 |
|------|--------|
| 공유드립니다 / 참고 바랍니다 (FYI) | 정보 알림 |
| 확인 부탁드립니다 | 입력 요청 |
| 검토 후 회신드리겠습니다 | 처리 대기 |
| 처리가 보류되었습니다 | 오답/실패 |
| 정상 처리되었습니다 | 정답/완료 |
| 사내 규정상 / 관련하여 | 제약 설명 |
| 유연하게 대응 부탁드립니다 | 모호한 지시 |
| 양해 부탁드립니다 | 페널티 알림 |
| 진행 바랍니다 | 액션 유도 |
| 수고하셨습니다 | 클리어 (이중적 어조) |
| 추가 업무 처리 모드 | 야근 |
| 정시 퇴근 | 정상 종료 |

### 12.3 카테고리별 템플릿

**알림 (헤더 라벨 `[ 사내 알림 ]`)**
> 출근 기록이 확인되지 않아 처리가 보류되었습니다. 담당자에게 확인 부탁드립니다.

**정답 처리 (`[ 처리 완료 ]`)**
> 입력 내용이 정상 처리되었습니다. 다음 단계로 진행 가능합니다.
> 수고하셨습니다, 사원님.

**오답 / 실패 (`[ 처리 보류 ]`)**
> 입력 내용이 사내 규정과 일치하지 않습니다. 재확인 부탁드립니다.
> ※ 처리 시간이 5분 추가 소요되었습니다.

**단서 / 아이템 획득 (`[ 자료 확보 ]`)**
> 「{item}」을(를) 업무 자료로 보관하였습니다.

**시간 표시 (헤더 시계 옆 라벨)**
> 현재 시각 {HH:MM} · 정시 퇴근까지 {N}분 (이벤트 단위 산정)

**시간 만료 (`[ 사내 알림 ]`)**
> 정규 근무 시간이 종료되었습니다. **추가 업무 처리 모드**로 전환합니다.
> 협조 부탁드립니다.

**선택지 결정 (대화 후)**
> 응답이 기록되었습니다. 검토 후 회신드리겠습니다.

**저장 성공 / 실패**
> ※ 진행 상황이 사내 시스템에 자동 보관되었습니다.
> ※ 사내 시스템 접근이 차단되어 있습니다. 세션 동안만 진행이 유지됩니다.

**메인 메뉴 버튼 (4개)**
> [ 출근하기 ]      ← 새 게임 (기존 세이브 있으면 덮어쓰기 1회 확인)
> [ 업무 복귀 ]      ← 이어하기 (세이브 없을 시 비활성·반투명)
> [ 인사 평가 기록 ] ← 해금 엔딩 목록 (`records.tscn` 전환)
> [ 퇴근하기 ]      ← 종료 (Web에서는 `[ 메인으로 ]`로 자동 분기, 실제 종료 X)

### 12.4 금지어 / 금지 표현

- 게임 RPG 용어: `퀘스트`, `레벨업`, `획득!`, `GET!`, `콤보`, `보너스`, `미션`

## 15. 회사·세계관 변수 (전역 상수)

자주 바뀔 수 있는 회사·세계관 정보는 `GameConfig` autoload 상수로 빼고, 모든 텍스트는 토큰 치환 방식으로 참조한다. 회사명을 바꿔도 한 곳만 고치면 전 게임에 반영.

### 15.1 GameConfig autoload

```gdscript
# autoload/GameConfig.gd
extends Node

const COMPANY_NAME       := "애니 주식회사"
const COMPANY_NAME_SHORT := "애니㈜"
const CEO_NAME           := "핑크 토끼"           # 사장 이름/별칭
const CEO_TITLE          := "대표이사"

# 부서·직책 (퍼즐 단서에 등장)
const DEPT_SALES_1       := "영업1팀"
const DEPT_HR            := "인사팀"
const DEPT_IT            := "IT팀"
const ROLE_TEAM_LEAD     := "팀장"
const ROLE_MANAGER       := "부장"
```

### 15.2 토큰 치환

`MessagesDB` 및 UI 라벨에서 회사·세계관 정보를 직접 박지 않고 토큰으로 작성. 표시 직전 `GameConfig`에서 치환.

```gdscript
# 예시
"안녕하세요, {COMPANY_NAME} {DEPT_HR}입니다."
→ "안녕하세요, 애니 주식회사 인사팀입니다."

"{CEO_TITLE} {CEO_NAME} 드림"
→ "대표이사 핑크 토끼 드림"
```

치환 함수:
```gdscript
func resolve(text: String) -> String:
    var out := text
    for key in ["COMPANY_NAME", "COMPANY_NAME_SHORT", "CEO_NAME", "CEO_TITLE",
                "DEPT_SALES_1", "DEPT_HR", "DEPT_IT", "ROLE_TEAM_LEAD", "ROLE_MANAGER"]:
        out = out.replace("{%s}" % key, GameConfig.get(key))
    return out
```

### 15.3 GDD 표기 규칙

이 GDD부터 회사명·대표명·부서명을 직접 표기하지 않고 토큰으로 표기한다 (예: `{COMPANY_NAME}`, `{CEO_NAME}`). 기획자가 변경 시 본 섹션의 상수만 갱신.
