# GDD Writer — 방탈출 게임 기획서 작성

방탈출 게임 디자인 문서를 아래 템플릿으로 작성한다.

## GDD 템플릿

```markdown
# [게임 제목] — 게임 디자인 문서

## 1. 게임 개요
- **장르:** 방탈출 싱글플레이어
- **테마:** [테마 설명]
- **목표:** [플레이어 목표]
- **예상 플레이 시간:** [X분]
- **엔진:** Godot 4.x

## 2. 스토리
[1~3문단의 스토리 배경. 플레이어가 왜 이 방에 있는지, 탈출 동기는 무엇인지.]

## 3. 방 구성
### 방 1: [방 이름]
- **분위기:** [묘사]
- **입장 조건:** 시작 / [이전 방 클리어]
- **탈출 조건:** [어떤 퍼즐을 풀면 다음 방으로]
- **오브젝트 목록:**
  | 오브젝트 | 상태 | 기능 |
  |---------|------|------|
  | [이름] | 잠김/열림/고정 | [설명] |

### 방 2: [방 이름]
[동일 구조]

## 4. 퍼즐 설계
### 퍼즐 1: [퍼즐 이름]
- **위치:** [방 이름]
- **유형:** [자물쇠/서랍/기계/암호/물리 등]
- **단서:** [어디서 단서를 얻는지]
- **정답:** [정답 조건]
- **힌트 1:** [가장 약한 힌트]
- **힌트 2:** [더 구체적인 힌트]
- **보상:** [클리어 시 얻는 것]
- **Godot 구현:** [어떤 노드/시그널로 구현할지]

## 5. 인벤토리 아이템
| 아이템 | 획득 방법 | 사용처 |
|--------|---------|--------|
| [이름] | [설명] | [사용 조건] |

## 6. 게임 루프
```
시작 → 방 탐색 → 오브젝트 조사 → 단서 획득 → 퍼즐 해결
    → 아이템 획득 → [반복] → 탈출 조건 충족 → 엔딩
```

## 7. 기술 요구사항 (Godot)
- 씬 수: [방 수 + UI 씬]
- 필요 시스템: 인벤토리, 씬 전환, 오브젝트 상태 관리, [저장/불러오기]
```

## 작성 원칙

- 퍼즐은 단서 → 행동 → 결과가 논리적으로 연결되어야 한다
- 첫 프로젝트라면 방 2~3개, 퍼즐 4~6개로 시작 권장
- "Godot 구현" 항목을 반드시 포함 — 개발자가 바로 구현할 수 있도록
- 퍼즐 간 의존 관계를 고려 (A를 풀어야 B 단서를 얻는 구조)
