# Puzzle Designer — 방탈출 퍼즐 설계

## 퍼즐 설계 프로세스

### 1단계: 퍼즐 유형 선택

방탈출에 적합한 퍼즐 유형 → 자세한 카탈로그는 [puzzle-catalog.md](references/puzzle-catalog.md)

| 유형 | 난이도 | Godot 구현 복잡도 | 초보 추천 |
|------|------|-----------------|---------|
| 숫자 자물쇠 | 쉬움 | 낮음 | ★★★ |
| 열쇠-자물쇠 | 쉬움 | 낮음 | ★★★ |
| 색상 패턴 | 보통 | 중간 | ★★ |
| 암호/코드 해독 | 보통 | 낮음 | ★★★ |
| 물건 조합 | 보통 | 중간 | ★★ |
| 순서 기억 | 어려움 | 높음 | ★ |
| 물리 퍼즐 | 어려움 | 높음 | ★ |

### 2단계: 단서-행동-결과 연결

좋은 퍼즐은 단서 → 행동 → 결과가 논리적:

```
단서: 책장에 꽂힌 책 3권이 빨강/파랑/초록 순서
행동: 같은 색 버튼을 같은 순서로 누름
결과: 비밀 서랍 열림
```

퍼즐을 설계할 때 반드시 확인:
- 단서 없이 정답을 알 수 있는가? (있으면 단서 추가)
- 우연히 맞출 수 있는가? (가능하면 조합 수 늘리기)
- 한 번 틀리면 영구 실패하는가? (방지 — 재시도 허용)

### 3단계: 힌트 시스템 설계

각 퍼즐마다 힌트 2개 준비:

| 힌트 레벨 | 내용 |
|---------|------|
| 힌트 1 (약) | 단서가 어디 있는지 방향만 제시 |
| 힌트 2 (강) | 단서 내용을 직접 알려줌 |

### 4단계: 퍼즐 의존 관계 설계

퍼즐들이 선형 혹은 가지 구조로 연결:

```
[시작]
  ↓
[퍼즐A: 열쇠 획득] → [퍼즐B: 상자 열기] → [최종 퍼즐: 출구]
                   ↗
[퍼즐C: 코드 획득]
```

순환 의존(A→B→A) 반드시 방지.

## Godot 구현 연결

퍼즐 유형별 Godot 구현 방식:

- **자물쇠/숫자 입력**: `LineEdit` 또는 `SpinBox` + 시그널 `text_submitted`
- **버튼 패턴**: `Button` 배열 + 상태 배열 비교
- **열쇠-자물쇠**: 인벤토리 아이템 존재 여부 확인
- **오브젝트 조사**: `Area2D` 클릭 감지 + `Label` 팝업

퍼즐 상태는 `GameState` 싱글턴(Autoload)에 저장 — 씬 전환 후에도 유지.
